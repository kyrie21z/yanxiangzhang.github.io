最近在开发 [Olympus4SWE](https://github.com/kyrie21z/Olympus4SWE)（一个面向全生命周期软件工程的 Agent-Native 系统）时，我停下来问了自己一个问题：我一直坚持“尽量零依赖”，这真的对吗？

回头看当时的代码库，运行时依赖被我压到只剩寥寥几个包，看起来很“干净”，代价却是：用 Python 标准库 `http.server` 自己写路由和 SSE 流，拿几千行没有类型检查的原生 JS 维护 Web 控制台，画图实在撑不住又在外面套了一层 React + Vite 的孤岛，连模型接口的 HTTP 协议方言也是自己手写的。

我原本以为这是在坚持第一性原理。仔细一想，其实是在疯狂重复造轮子。

## 一、第一性原理不是“从零手写”

做工程从第一性原理出发，这件事本身毋庸置疑，之前是这样，以后也不会变。但我之前把“第一性原理”误解成了“一切从零开始写”。

马斯克造火箭的初期，也不是一上来就把所有零配件全部自研。他先用成熟的商用现成组件把系统搭出来，直到发现某些部件的采购成本高得离谱，或者性能与交付直接卡死了核心目标，才回到物理与成本的第一性原理去自研替代。

软件工程也是一样。那些成熟依赖被开发出来，本来就是给人、给项目依赖的。做项目真正的第一性约束，不是依赖清单有多短，而是**用更低的研发与维护成本，尽快把核心闭环搭出来并验证关键假设**。把第一版的目标定得比天还高，事无巨细都从零打造“完美”，这个需求本身就不符合第一性原理。

## 二、拒绝黑盒框架，不等于拒绝所有依赖

拆开来看，我最初排斥引入依赖，真正防备的其实是另一类东西——把核心控制流、状态迁移和 Prompt 藏进厚重抽象里的重型编排框架。一旦把“拒绝重型黑盒”等同于“拒绝所有外部依赖”，就很容易掉进纯粹性陷阱。

按第一性原理重新划线，项目里的代码其实只分三层：

- **必须自研的核心护城河**：直接决定系统灵魂、交出去就会失去控制权的部分。在 Olympus4SWE 里，是需求对齐到架构设计的阶段契约、确定性状态机、并发写范围校验、审批绑定以及独立验收门禁。
- **果断借用的通用基础设施**：手写得再漂亮，也不会让核心任务解决率提高 0.1%，反而持续吞噬精力的部分。比如标准 Web 服务（FastAPI + uvicorn）、统一的前端工程（React + TypeScript + Vite），以及各家模型官方 SDK 已经维护好的协议与流式细节。
- **保持克制的侵入式黑盒**：真正应该警惕的，是那些夺走控制权、让排错变成猜谜的重型编排框架。拒绝它们是为了透明与可控，不是为了“零依赖”的仪式感。

先用成熟的依赖把项目搭稳，后续如果真的在实测中遇到性能瓶颈或可控性问题，再有针对性地自研替换，这才是把第一性原理用在了刀刃上。

## 三、不追求一开始完美，为什么现在反而该重构？

顺着上面的逻辑，很容易得出一个传统结论：既然不能追求一开始就完美，那就先将就着跑，等以后真出问题再重构。

但我觉得，**现在反而是重构的最佳时机。**

项目目前依然处在搭建 codebase 的阶段：核心领域边界已经验证清楚，同时还没有沉重的历史包袱。更重要的是，在 AI Agent 深度参与编码的今天，传统工程里“先欠点债、以后慢慢还”的账已经算不平了。

这个意识来自 Lauren Tan 的演讲 [*All Code Is Slop (Except Mine)*](https://www.youtube.com/watch?v=O_zcc6Xl12g) 中一个很戳人的观点：**Codebase 本身就是 Agent 的记忆和护栏。**

Agent 写新代码时，不会老老实实记住你在文档里写了多少条“不要怎么做”，它最诚实的学习样本就是仓库里已经存在的代码模式。如果仓库里躺着几千行无类型的原生 JS、手写的弱约束 HTTP 路由，以后派给 Agent 的每一个新功能，都会顺着这些坏模式继续长下去——在人类手写代码的时代，技术债大多是线性累积的；在 Agent 时代，坏架构会被成倍放大。

反过来，趁现在还处在搭底座的窗口期，把通用基础设施切到成熟生态，把约束写进编译器和静态检查里（例如用强类型后端契约自动约束前端类型，配合严格的 lint 与自动化测试），坏代码在提交前就会被确定性地拦下来。之后的每一次开发，都会因为今天立好的底座而事半功倍；否则以后的努力，很大一部分只是在为今天的怠惰买单。

## 结语

“不要一开始追求完美”和“趁早打磨一个尽可能好的 codebase”并不矛盾。

前者提醒我们，不要陷入零依赖洁癖，去重复造本该直接复用的轮子，也不要为假想的未来过度设计；后者提醒我们，底座阶段的偷懒会在 AI 加速迭代后变成高昂的返工税。把通用轮子还给生态，把确定性护栏刻进代码库，把精力留给真正值得从第一性原理去攻克的问题——这大概才是更清醒的工程节奏。
