01

斯坦福的生成式智能体——“Smallville”

Park、O'Brien、Cai、Morris、Liang 与 Bernstein，UIST 2023（最佳论文）。25 个 由 LLM 驱动的智能体生活在一个类似《模拟人生》的 2D 瓦片地图小镇中，跨越多个游戏日。每个智能体都有 人设、记忆、日常作息和人际关系——没有脚本；行为由人格描述加上亲身经历生成。原始在线演示已下线，但代码是 开源的，论文可免费获取。

论文：arxiv.org/abs/2304.03442 · 代码：github.com/joonspk-research/generative_agents

要点：这是可信 LLM 智能体的基础架构 ——记忆流 + 反思 + 规划——也是几乎所有后续智能体记忆 工作（MemGPT、Zep 以及下文的框架）所依托的基线。

可信度：完整架构 vs 消融实验

来自一项有 100 名人类评分者参与的受控评估的 TrueSkill μ 值。完整 架构击败了每一个消融版本——也击败了由人类众包工作者手工编写的智能体。完整版 vs 无记忆版的 Cohen's d = 8.16，论文将其描述为“代表了此前最先进的水平”。

反思是可信度提升的最大单一贡献因素 ——这正是上文循环值得忠实实现、而不是简单地把 LLM 套在状态机上的原因。

局限与成本

  • 真实 API 成本。基于 gpt-3.5-turbo 构建；长时间的多智能体运行需要花真金白银——按 2023 年的价格，每次运行需数十美元。没有任何来源给出 Smallville 的确切账单（见待核实问题）。如今在本地模型上复现是免费的。
  • 速度慢。顺序执行的观察 → 反思 → 规划循环是延迟瓶颈；没有任何环节以帧率运行——世界以模拟节拍推进。
  • 失效模式。智能体会陷入重复循环、幻觉出不存在的事件，并在缺乏记忆锚定时逐渐跑偏。这是一个研究原型，不是游戏引擎集成方案。
  • 代码已冻结。2023 年的 Python 代码库，锁定在早期的 OpenAI API 上，是一个参考实现，而非持续维护的产品。现代的重新实现（AI Town、Concordia）是更好的起点——但架构模式本身仍然是标准。

2024 年的后续研究：1000 名真实的人

Park 等人的《1000 人的生成式智能体模拟》 （2024）将智能体建立在对 1052 名真实个体的定性访谈之上，并以 85% 的准确率复现了综合社会调查（General Social Survey）的回答 ——这是个体层面行为保真度的黄金标准，且目前仍然是最新的，未被取代。

论文：arxiv.org/abs/2411.10109。 第一作者 Joon Sung Park 此后共同创立了 Simile AI，致力于 将该方法商业化。

Google DeepMind 的 Concordia

Vezhnevets 等人（Google DeepMind），arXiv 2023 年 12 月。Concordia 是一个用于构建 语言介导模拟的库——“将 Smallville 做成一个库”。智能体通过一个灵活的 组件系统产生行为，该系统协调两个基本操作：LLM 调用和联想记忆 检索。一个特殊的智能体——游戏主持人（Game Master, GM）——借鉴自桌面角色扮演游戏，负责模拟 环境：智能体通过用自然语言描述自己想做什么来采取行动， GM 则将这些描述转化为具体结果，在物理世界中检查物理合理性，或在数字世界中发出真实的 API 调用。它是为科学研究而设计的 ——用于实验、数字服务评估和合成数据——而不是作为一款游戏。

论文：arxiv.org/abs/2312.03664 · 代码：github.com/google-deepmind/concordia · PyPI 包：gdm-concordia

要点：这是用于生成式智能体建模的研究级、持续维护的 Python 框架 ——而其游戏主持人模式（LLM 提出，引擎裁决）是最值得借鉴到你自己游戏中的、最干净的行动裁决设计。

其他标志性多智能体世界项目

两大支柱之外的规模扩展与范式开创者——当你把智能体数量推高、赋予智能体可执行技能，或将模拟连接到消息总线上时，会发生什么。

Project Sid

Altera · arXiv 2024 年 10 月 · Minecraft

论文 — arxiv.org/abs/2411.00114 代码 — github.com/altera-al/project-sid MIT Technology Review 报道

Smallville 的 40 倍放大——25 个智能体变成了多达 1000+ 个智能体，在 Minecraft 中运行（实验涵盖了从 10 个智能体起的多种配置），并发展出 角色、经济、宪法和宗教。其关键使能技术是 PIANO（通过神经编排的并行信息聚合）：约 10 个并发的认知模块 ——说话、行动、规划、社会意识、目标生成、记忆——由一个瓶颈式的“认知控制器”聚合，使智能体可以慢思考、快行动，实时运作。

涌现了什么：专业化分工 （农民、矿工、商人、祭司、守卫）、一个使用宝石货币的商人枢纽、一部在共享 Google 文档中投票通过并修订的宪法、通过贿赂传播的飞面神教（Pastafarianism），以及社区之间的迷因传播。

局限：超过 1000 个智能体后，Minecraft 服务器的算力耗尽（智能体间歇性无响应），且 关于智能体究竟有多自主、多依赖脚手架的问题仍然存在。Altera——首席执行官 Robert Yang， 前 MIT 研究人员——在 2024 年 5 月筹集了 900 万美元种子轮融资，致力于打造“数字人类”。

Voyager

Wang 等人，NVIDIA 等 · arXiv 2023 年 5 月 / TMLR 2024 · Minecraft

论文 — arxiv.org/abs/2305.16291 项目网站 — voyager.minedojo.org

虽然是单智能体，却具有奠基意义——这是经典的技能 库论文，也是 Minecraft 中第一个基于 GPT-4 的具身终身学习者，且无需 微调。三大要素：（1）自动课程；（2）一个不断增长的 可执行代码技能库，技能可被检索和组合——将记忆做成代码，从而缓解 灾难性遗忘；（3）结合环境反馈、执行错误和基于真实游戏状态的自我验证的迭代式提示。

成果：获得的 独特物品数量是此前最先进方法的 3.3 倍，达到木制工具里程碑的速度快 15.3 倍，探索距离长 2.3 倍；学到的技能可以迁移到新世界。这种“技能库即记忆”的模式可以直接复用到你自己项目中的 NPC 技能系统。

05

学生开发者需要掌握的核心技术

上述论文背后的实操知识——如何构建一个智能体、如何让智能体高效交流、如何将预算控制在 0 美元、如何接入游戏引擎，以及如何证明结果确实是涌现的。

架构感知 → 记忆 → 规划 → 行动

  • 感知 = 文字化描述。LLM 基于文本进行推理，因此每个节拍都要将游戏状态序列化为自然 语言：“你在厨房里。Alice 在这里。你饿了。”
  • 记忆分为三层：存放近期事件的短期工作缓冲区；带有新近度/重要性/相关性检索的长期 记忆流；通过反思/总结将历史压缩为持久信念。对于技能密集型智能体，Voyager 的技能库—— 将记忆做成可执行代码——比文本日志更有效。
  • 规划是分层的（天 → 小时 → 行动），并会根据事件重新规划。将快速 反应循环（对话、反应）与慢速深思循环分开——即 PIANO 式的并行。
  • 行动必须经过裁决器。自然语言意图 → 一个游戏主持人式的 验证器，负责检查游戏规则并应用效果。绝不能让 LLM 直接修改游戏状态。

协调多智能体通信

  • 使用结构化的、带收件人的协议——发送者、接收者、意图、紧急程度——而不是 自由形式的群聊。共享消息池 / 黑板（MetaGPT）可以减少广播开销。
  • 拓扑结构很重要。中心化协调者适合顺序任务；去中心化的 辩论/对话适合并行创意任务。Google Research 对 180 种配置的研究 （2026 年 1 月）发现，多智能体协调能提升可并行任务的表现，却会损害顺序任务——而没有通信的独立智能体会将错误放大多达 17.2 倍。要有意识地设计通信，而不是事后补上。
  • 防止聊天死循环：加入冲突解决机制（辩论循环、投票，或由 GM 裁决）并为每个智能体设定回合预算——无限对话循环是 CAMEL 时代已知的失效模式。

性能控制成本与延迟

  • 绝不要每帧调用 LLM。让世界以模拟节拍（秒级）运行，LLM 调用异步进行、置于游戏循环之外——AI Town 的模式是：将每秒 60 个引擎节拍批量合并为每秒 1 个持久化步骤。
  • 模型级联：用小而快的模型处理日常反应，大模型只用于 规划和反思——或者用一个本地小模型包办一切。
  • 本地推理 = 边际成本 0 美元。Ollama + 量化的 .gguf 模型； LLMUnity 可在 Unity 引擎内运行，Laya 报告本地决策在 GPU 上仅需 5–40 毫秒。
  • 延迟技巧：将 token 流式输出到对话中（先文字，后语音）；在玩家靠近时预取 NPC 可能的台词；缓存重复台词（店主的问候语成本 近乎为零）；用 Opus 压缩音频。
  • 严格控制预算：为每个智能体的每个节拍设定固定的 token 预算；反思是最昂贵的 部分——要少运行。

集成游戏引擎接入

  • Unity —— LLMUnity：通过 Package Manager 中的 git URL 安装；可运行本地 .gguf 模型（llama.cpp），提供 LLMAgent 组件和流式 Chat() API。这是文档最完善的 Unity 路径。
  • Unreal：没有占主导地位的开源插件；有文档记录的模式是使用一个本地 TCP 服务器 （Python/Node）托管 LLM + TTS，Unreal 作为客户端（见 “Breaking the Cloud Barrier,” OpenReview）。
  • Godot：通过 HTTP 使用相同的客户端–服务器模式——用 HTTPRequest 请求本地 Ollama/Concordia 服务器。与引擎无关，且最简单。
  • Minecraft：事实上的研究世界——成本低、真值确定（方块 状态）。标准工具是机器人库（Mineflayer/Malmo 系列）；Altera、Voyager 和 Project Sid 都构建在 Minecraft 服务器之上。
  • 最快的课程路径：跳过引擎——将世界做成 Web 应用 / Canvas（像 AI Town 的 PixiJS 瓦片地图）或 Python + Pygame。你会失去 3D 的精美度，但能省下数周时间。

评估涌现行为

  • 可信度评估：借鉴 Park 等人的 TrueSkill 式人类 评分——向评分者展示带与不带你的功能的智能体行为日志。消融实验是你能产出的成本最低、最有力的证据。
  • 对照目标进行验证：Park 等人 2024 年的工作（对综合社会调查达到 85%）是范本，但对课程来说太重。更简单的做法：预先定义目标涌现 现象——信息扩散、角色分化、规范形成——并进行具体测量：网络密度、传播曲线、规则变更次数。
  • 可借鉴的基准：SimBench （arXiv:2510.17516，2025）用于人类行为 模拟保真度；Project Sid 的文明级基准——角色专业化、 集体规则变更、文化传播——可作为观察清单。
06

实用的入门路径

按课程作业的规模来定：几周时间，一台机器，没有 API 账单。

最小可行的多智能体世界游戏

一个 2D 瓦片村庄，3–8 个智能体，一个本地 LLM

智能体会醒来、去工作、吃饭，并在同处一地时聊天，运行 Park 循环（记忆流 + 反思 + 规划），并以浏览器 Canvas 或 Pygame 地图的形式呈现。加入一个共享事件日志和 一个种子事件——一场派对的传闻，或一次市长选举。以每真实秒 1 游戏分钟的速度模拟时间。一切都在本地通过 Ollama 运行，成本为 0 美元。可在 2–3 周内复现，且可演示。

推荐框架（按顺序）

a16z AI Town

采用 MIT 许可证的 TypeScript 入门套件，重新实现了 Smallville：Convex 后端（节拍引擎、 向量搜索记忆、事件日志）、PixiJS 地图，可插拔的 OpenAI/Ollama。 如果你想最快做出一个可运行的演示，这个最合适。

Google DeepMind Concordia

Python，可通过 pip 安装（gdm-concordia），采用游戏主持人模式进行裁决，附带教程 笔记本。如果作业看重干净的架构且你想用 Python，这个最合适。

LLMUnity

带有引擎内本地 LLM 推理的 Unity 包。 如果作业要求使用 Unity，这个最合适。

Minecraft + 机器人库

Malmo/Mineflayer 系列。如果你想要 Project Sid / Voyager 风格的 具身智能体，这个最合适——但搭建成本最高。

三个项目构想（已限定范围）

1 · 谣言传播村庄

Fork AI Town：在一个 Smallville 风格的小镇中放置 5 个智能体。植入一条谣言，测量在有反思和无反思情况下的信息 扩散和态度变化——消融研究就是你的评估章节。

技术栈
AI Town Fork
时间
约 2 周
交付成果
可玩的小镇 + 传播曲线

2 · 带有宪法的小型文明

6–10 个智能体在 Concordia 中共享一种资源（一个鱼塘、一座花园）。他们必须通过游戏主持人提出、投票和修订规则；你则追踪规则的涌现和违规行为。

技术栈
Concordia
时间
约 3 周
交付成果
规则变更日志 + 可持续性指标（参见 GovSim）

3 · Unity 微型游戏中的 LLM 任务发布 NPC

一个 5 分钟的 Unity 地牢，包含 3 个 NPC——店主、任务发布者、守卫——通过 LLMUnity 由本地模型驱动。NPC 们共享对玩家行为的记忆，并据此改变对话和任务。

技术栈
Unity + LLMUnity
时间
约 2–3 周
交付成果
可玩的构建版本 + 延迟/成本测量，证明在消费级硬件上实时运行的可行性
